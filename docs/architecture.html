omadsp architecture

Design from the Phase 0 findings (ADR-1 to ADR-11). The signal path runs left to right; the daemon controls it from below.

Apps

Browsers, players, games: anything playing to the default device

→

Capture node

omadsp
WirePlumber smart filter, Audio/Sink, no target: follows the default device. Preamp = ramped volume

→
child process: pipewire -c host.conf (filter-chain), supervised by omadspd

pre

LSP para_equalizer_x16_lr
device correction (AutoEq) + bass / treble shelves

→

eq

LSP para_equalizer_x32_lr
graphic or parametric EQ, up to 32 bands, click-free drags

→

lim

LSP limiter_stereo
always last, true peak, −1 dBTP ceiling

→

Playback node

omadsp_out
ramped volume for dips, A/B and on/off without reloads

→

Device

Speakers, USB DAC, Bluetooth. Its own volume applies after the DSP

▲ set_param (≤ 1 per node per 16 ms)  ·  filters metadata (DSP off = smart filter disabled)  ·  supervise host  ·  passive tap on omadsp_out for the overload LED
omadspd: Rust daemon, systemd --user Phase 1 in progress

model

presets, device profiles, state; single source of truth

graph

pure fn(preset) → host.conf; fixed topology, golden-file tests

dsp_math

RBJ biquads, combined response curve, auto-headroom

pw

PipeWire client: registry, default sink, params, links

host

writes the conf, spawns and watches the filter host

ipc

NDJSON v1 over $XDG_RUNTIME_DIR/omadsp/omadsp.sock
